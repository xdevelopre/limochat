# Limo Chat v1.11

این بسته بر پایهٔ فایل‌های ارسالی شما ساخته شده است. فایل‌های سورس minify نشده‌اند. آرشیو ZIP نیز با روش `ZIP_STORED` ساخته شده؛ یعنی فایل‌های داخل ZIP فشرده نمی‌شوند.

## تغییرات این نسخه

- لینک دعوت و اشتراک‌گذاری در همهٔ بخش‌های برنامه: `https://xdevelopre.github.io/limochat/`
- گفتگوی عمومی در فهرست گفتگوها وجود دارد و از جدول مشترک `global_messages` استفاده می‌کند.
- سقف ارسال در دیتابیس اعمال می‌شود: حداکثر **۵ پیام در هر بازهٔ شناور ۳۰ ثانیه‌ای برای هر حساب**؛ شمارش بین چت خصوصی و عمومی مشترک است. متن و تصویر هر دو پیام حساب می‌شوند.
- محدودکنندهٔ محلی فقط بازخورد سریع می‌دهد؛ محدودیت PostgreSQL مرجع نهایی است و درخواست‌های هم‌زمان را نیز سریالی می‌کند.
- ساخت گفتگوی خصوصی از RPC امن استفاده می‌کند و یک درخواست اضافی خواندن اعضا که می‌توانست به RLS برخورد کند حذف شده است.
- ارسال پیام تا زمان تأیید سرور متن را از کادر پاک نمی‌کند؛ خطای به‌روزرسانی پیش‌نمایش چت، ارسال موفق پیام را ناموفق نشان نمی‌دهد.
- خطاهای دسترسی، محدودیت، نبود جدول و خطای شبکه به پیام قابل‌فهم تبدیل می‌شوند؛ جزئیات فنی فقط در Console مدیر ثبت می‌شوند.
- دکمهٔ ورود دیگر عبارت اتصال به سرویس یا نام ارائه‌دهنده را نشان نمی‌دهد.
- انیمیشن‌ها و واکنش دکمه‌ها نرم‌تر شده‌اند و تنظیم `prefers-reduced-motion` حفظ شده است.
- در ارسال عکس، اگر ذخیرهٔ پیام رد شود فایل آپلودشدهٔ بدون پیام نیز حذف می‌شود.

## انتشار فایل‌های سایت

1. از مخزن GitHub فعلی نسخهٔ پشتیبان بگیرید.
2. محتوای پوشهٔ این بسته را در ریشهٔ مخزن `xdevelopre/limochat` جایگزین کنید؛ `index.html` باید در ریشه باشد.
3. Commit و Push کنید و منتظر تکمیل انتشار GitHub Pages بمانید.
4. آدرس دعوت: https://xdevelopre.github.io/limochat/

## به‌روزرسانی دیتابیس موجود (v1.10)

ابتدا از دیتابیس نسخهٔ پشتیبان بگیرید. سپس در Supabase Dashboard → SQL Editor فایل `supabase-v1.11-update.sql` را یک‌بار اجرا کنید. این اسکریپت RPC ساخت گفتگوی خصوصی و محدودیت قطعی ۵ پیام در ۳۰ ثانیه را با هم اصلاح می‌کند و داده‌های کاربران/پیام‌ها را حذف نمی‌کند.

نسخه‌های جداگانهٔ `supabase-chat-repair.sql` و `supabase-rate-limit.sql` نیز برای اجرای مرحله‌ای در بسته هستند. اگر قبلاً مشکل پروفایل کاربر داشته‌اید، `supabase-profile-repair.sql` نیز موجود است.

اگر جدول‌های پایه مثل `profiles` یا `messages` هنوز ایجاد نشده‌اند، فایل کامل `supabase-schema.sql` را اجرا کنید؛ در دیتابیس دارای دادهٔ مهم ابتدا Backup بگیرید.

## بررسی سلامت نصب دیتابیس

پس از اجرای migrationها، این SQL را اجرا کنید تا وجود triggerها تأیید شود:

```sql
select
  c.relname as table_name,
  t.tgname as trigger_name,
  pg_get_triggerdef(t.oid) as trigger_definition
from pg_trigger t
join pg_class c on c.oid = t.tgrelid
join pg_namespace n on n.oid = c.relnamespace
where n.nspname = 'public'
  and t.tgname in ('limo_rate_limit_private_messages', 'limo_rate_limit_global_messages')
  and not t.tgisinternal
order by c.relname;
```

باید دو ردیف برای `messages` و `global_messages` دیده شود.

## نکتهٔ امنیتی مهم

پنهان‌کردن متن «در حال اتصال» فقط ظاهر رابط را تغییر می‌دهد؛ نشانی endpoint و کلید عمومی (publishable/anon) که مرورگر برای ارتباط لازم دارد، از طریق کد و درخواست‌های شبکه قابل مشاهده است. این کلید به‌خودی‌خود رمز مدیریتی نیست و نباید کلید `service_role` در فایل سایت قرار بگیرد. امنیت واقعی به RLS صحیح، محدودیت دسترسی جداول/Storage، محدودیت نرخ سمت دیتابیس، سیاست‌های Auth و به‌روزرسانی امن وابسته است. این بسته نام سرویس را از پیام‌های عادی رابط حذف می‌کند، اما دیتاسنتر را از نظر فنی مخفی نمی‌کند.

## محدودیت اعتبارسنجی

فایل‌ها و ساختار SQL/JavaScript در این محیط بررسی ایستا می‌شوند؛ امکان ورود به پروژهٔ واقعی شما و اجرای migration روی دیتابیس زنده در اینجا وجود ندارد. بنابراین برای تأیید نهایی، اجرای موفق SQLها و آزمایش با دو حساب واقعی لازم است. اگر پس از اجرای migration همچنان خطایی دیدید، پیام جدید برنامه عمومی و قابل‌فهم خواهد بود و علت دقیق برای مدیر در Console مرورگر ثبت می‌شود.
