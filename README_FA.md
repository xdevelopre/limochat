# Limo Chat v1.10 — Supabase Profile Repair

این نسخه بر پایه فایل v1.09 است و خطای «ورود موفق بود اما پروفایل بارگذاری نشد» را در مسیر پروفایل اصلاح می‌کند.

## فایل‌ها

- `index.html` — رابط کاربری و کلاینت Supabase.
- `supabase-profile-repair.sql` — اصلاح فوری دیتابیس موجود v1.09 برای ساخت امن پروفایل حساب‌های قدیمی.
- `supabase-schema.sql` — شِمای کامل برای نصب تازه؛ شامل تابع اصلاح پروفایل نیز هست.
- `README_FA.md` — راهنمای نصب.

## چرا خطای پروفایل رخ می‌داد؟

در کد قبلی، اگر کاربر قبل از نصب Trigger مربوط به `auth.users` ساخته شده بود، ممکن بود ردیف متناظر در `profiles` نداشته باشد. کلاینت بعد از ورود تلاش می‌کرد آن را مستقیم درج کند، اما اسکریپت قبلی به نقش `authenticated` مجوز `INSERT` و سیاست RLS مربوط به آن را نداده بود. در نتیجه احراز هویت موفق می‌شد اما دریافت/ایجاد پروفایل شکست می‌خورد.

در این نسخه، تابع `ensure_limo_profile()` با `SECURITY DEFINER` فقط برای شناسه‌ای که از `auth.uid()` می‌گیرد پروفایل می‌سازد یا موجود را بازمی‌گرداند. کلاینت دیگر مجوز درج مستقیم روی جدول `profiles` نمی‌خواهد. همچنین بارگذاری تنظیمات اختیاری از بارگذاری پروفایل جدا شده تا خطای یک جدول فرعی، کل ورود را خراب نکند.

## نصب روی پروژه‌ای که v1.09 را قبلاً نصب کرده است

1. از Supabase یک نسخه پشتیبان بگیر.
2. وارد **Supabase → SQL Editor → New query** شو.
3. فقط محتوای `supabase-profile-repair.sql` را اجرا کن و مطمئن شو اجرای آن با Success تمام شده است.
4. فایل `index.html` نسخه 1.10 را در ریشه GitHub جایگزین نسخه قبلی کن و Commit/Push بزن.
5. بعد از پایان Deploy در Cloudflare Pages، سایت را در Chrome با HTTPS باز کن. برای اطمینان یک بار Hard refresh انجام بده.
6. با همان آیدی و رمز قبلی وارد شو. نیازی به حذف حساب یا پاک‌کردن کاربران نیست.

**مهم:** برای پروژه‌ای که هنوز شِمای کامل v1.09 را نصب نکرده، به‌جای migration کوچک بالا، فایل کامل `supabase-schema.sql` را اجرا کن. آن را بدون نسخه پشتیبان روی دیتابیسی که داده مهم دارد اجرا نکن.

## تغییرات اصلی v1.10

- دریافت پروفایل موجود، سپس فراخوانی RPC امن برای ایجاد پروفایل مفقود.
- تشخیص خطای نبود تابع، نبود جدول، خطای RLS و خطای شبکه با پیام متناسب.
- تنظیمات، وضعیت چت و فهرست مسدودها دیگر شرط موفقیت دریافت پروفایل نیستند.
- اگر پروفایل معتبر باشد، ورود تکمیل می‌شود حتی اگر بارگذاری داده‌های اختیاری مشکل داشته باشد.
- فایل‌ها minify نشده‌اند و سورس HTML قابل ویرایش است.

## نکات امنیتی و عملیاتی

- کلید `sb_publishable_...` در مرورگر عمومی است و برای کلاینت طراحی شده؛ از `service_role` در HTML استفاده نکن.
- جدول `profiles` باید RLS و سیاست خواندن کاربران احراز هویت‌شده را طبق شِمای کامل داشته باشد.
- این بسته اجرای واقعی روی پروژه Supabase شما را از محیط تولید تأیید نمی‌کند؛ پس اجرای موفق migration در SQL Editor و آزمایش با حساب واقعی، معیار قطعی است.
- اگر پس از نصب migration باز هم خطا دیدی، متن کامل Toast یا خطای Console (به‌خصوص `code`, `message`, `details`) برای تشخیص مرحله بعد لازم است.
